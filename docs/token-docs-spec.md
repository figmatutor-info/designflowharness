# 토큰 문서 규격 (Token Docs Spec)

`01 Tokens` 페이지에 그려지는 **토큰 문서 프레임**의 레이아웃 계약이다.
사람이 읽는 SSOT 이고, 이 규격을 구현한 것이 `scripts/figma-token-docs.js`,
지켜졌는지 판정하는 것이 `scripts/check-token-docs.mjs` 다.

> **왜 계약으로 고정하나**
> 예전 지시는 "스와치 프레임 하나 그림 (내부 검증용)" 한 줄이 전부였다.
> 치수·그리드·카드 구조가 없으니 실행할 때마다 다른 것이 나왔고,
> 실제로 2016×146 짜리 한 줄 띠에 라벨이 칩 위에 겹쳐 잘린 산출물이 나왔다.
> `figma-snapshot.js` 와 같은 처방이다 — **즉흥 작성 금지, 파일 하나로 고정.**

---

## 1. 만드는 문서 (6개 프레임)

| 프레임 이름                              | 내용                     | 카드 1장의 의미                         |
| ---------------------------------------- | ------------------------ | --------------------------------------- |
| `Token Documentation — Color Primitives` | primitives 컬렉션 COLOR  | 색 칩 + 토큰명 + HEX                    |
| `Token Documentation — Color Semantic`   | semantic 컬렉션 COLOR    | 색 칩 + 토큰명 + `→ primitive명`        |
| `Token Documentation — Scale Primitives` | primitives 컬렉션 FLOAT  | 길이 바 + 토큰명 + 값                   |
| `Token Documentation — Scale Semantic`   | semantic 컬렉션 FLOAT    | 길이 바 + 토큰명 + `→ primitive명 · 값` |
| `Token Documentation — Typography`       | `Text/*` 텍스트 스타일   | 샘플 글자 + 스타일명 + `크기/굵기`      |
| `Token Documentation — Shadow`           | `Shadow/*` 이펙트 스타일 | 그림자 적용 카드 + 스타일명             |

프레임은 캔버스에 가로로 나란히 놓는다. x = `i × 1400`, y = `0`.

**누락·유령 금지.** 각 컬렉션/스타일의 항목은 **정확히 1회씩** 카드로 나타나야 한다.
변수는 있는데 카드가 없거나, 카드는 있는데 변수가 없으면 게이트 FAIL 이다.

## 2. 프레임 구조

```
Token Documentation — {문서명}          1280 wide · 세로 스택 · bg #FFFFFF
├─ _Status                              h64
│   ├─ text  좌 x32  y23.5   프로젝트 라벨 (대문자, 11/600, 자간 +0.08em)
│   └─ text  우 x1168 y23.5  날짜 (SEP 17, 2026 형식)
├─ Title                                h192
│   ├─ text  x64 y56   문서 제목            32/700
│   └─ text  x64 y115  한 줄 설명           15/400  muted
└─ Section · {그룹}  (그룹 수만큼 반복)   상단 1px 헤어라인
    ├─ Section Header   x64 y33 w1152 h40
    │   ├─ text  x0    그룹 한글 라벨        18/600
    │   └─ text  x532  우측 안내문 w620      13/400  faint
    └─ Token Grid       x64 y93 w1152
        └─ {토큰명}  (카드)
```

### 섹션 높이

```
행 수 rows = ceil(카드수 / 5)
그리드 높이 = rows × 136 + (rows − 1) × 16
섹션 높이   = 93 + 그리드 높이 + 32
```

### 프레임 전체 높이

```
64 (Status) + 192 (Title) + 모든 섹션 높이의 합
```

## 3. 그리드와 카드 (모든 문서 공통)

| 항목       | 값                                             |
| ---------- | ---------------------------------------------- |
| 열 수      | **5**                                          |
| 카드 크기  | **214 × 136**                                  |
| 가로 pitch | **230** (카드 214 + 간격 16)                   |
| 세로 pitch | **152** (카드 136 + 간격 16)                   |
| 카드 좌표  | `x = col × 230`, `y = row × 152` (그리드 기준) |

### 카드 내부 (고정)

```
{토큰명}                        214 × 136 · bg #FFFFFF · border 1px #E5E7EB · radius 10
├─ Swatch · {토큰명}            x13 y13  190 × 56   ← 시각 영역. 문서 종류별로 내용만 다름
├─ text  {토큰명}               x13 y77  w190 h20   13/500
└─ text  {값 또는 → 참조}       x13 y105 w190 h20   12/400  muted
```

**라벨을 칩 위에 얹지 않는다.** 칩과 라벨은 항상 분리된 영역이다. (기존 산출물의 실패 원인)

### `Swatch · {토큰명}` 영역의 문서별 내용

| 문서          | 내용                                                                            |
| ------------- | ------------------------------------------------------------------------------- |
| Color (둘 다) | 190×56 rounded-rect(radius 6). **fill 은 해당 변수를 바인딩**한다 (리터럴 금지) |
| Scale (둘 다) | 투명 프레임 안에 길이 바 1개 — 높이 12, 너비 `min(값, 190)`, 최소 4, `#3D5AFE`  |
| Typography    | 해당 텍스트 스타일을 적용한 샘플 `가나다 Ag 123`                                |
| Shadow        | 흰 rounded-rect(radius 10) + 해당 이펙트 스타일 적용                            |

## 4. 그룹핑 규칙 (섹션이 나뉘는 기준)

토큰 이름의 **첫 하이픈 앞**을 그룹 키로 쓴다. `color-*` 로 시작하는 semantic 색상만
예외적으로 **두 번째 조각**을 키로 쓴다 (`color-text-muted` → `text`).

그룹은 아래 표 순서대로 배치하고, 표에 없는 키는 **표 뒤에 알파벳 순**으로 붙인다.
(새 토큰 계열이 생겨도 문서가 깨지지 않게 하기 위한 장치 — 라벨은 키 그대로 쓴다)

| 키      | 한글 라벨 |     | 키      | 한글 라벨      |
| ------- | --------- | --- | ------- | -------------- |
| brand   | 브랜드    |     | bg      | 배경           |
| neutral | 뉴트럴    |     | surface | 표면           |
| red     | 레드      |     | border  | 보더           |
| green   | 그린      |     | text    | 텍스트         |
| amber   | 앰버      |     | primary | 프라이머리     |
| teal    | 틸        |     | danger  | 위험           |
| overlay | 오버레이  |     | success | 성공           |
| space   | 간격      |     | warning | 경고           |
| radius  | 라운드    |     | status  | 상태           |
| size    | 크기      |     | safe    | 세이프에어리어 |
| icon    | 아이콘    |     | app     | 앱바           |
| tab     | 탭바      |     |         |                |

### 우측 안내문 (섹션 헤더 오른쪽)

| 문서            | 문구                                                          |
| --------------- | ------------------------------------------------------------- |
| Primitives (둘) | `원시 값입니다. 제품 UI에서는 시맨틱 토큰을 통해 참조하세요.` |
| Semantic (둘)   | `제품 UI는 이 계층만 참조합니다. 값은 프리미티브에서 옵니다.` |
| Typography      | `role 기반 텍스트 스타일입니다. 크기를 직접 쓰지 마세요.`     |
| Shadow          | `이펙트 스타일입니다. 그림자를 직접 그리지 마세요.`           |

## 5. 색·폰트 (문서 크롬의 예외 규정)

토큰 문서는 **제품 UI 가 아니라 메타 레이어**다. 문서의 배경·선·라벨 텍스트는
프로젝트 semantic 토큰을 쓰지 않고 아래 고정값을 쓴다. 프로젝트마다 문서 껍데기 색이
달라지면 문서끼리 비교가 안 되기 때문이다.

| 용도               | 값        |
| ------------------ | --------- |
| 문서 배경 / 카드   | `#FFFFFF` |
| 헤어라인 / 카드 선 | `#E5E7EB` |
| 본문 텍스트        | `#111827` |
| 보조 텍스트        | `#6B7280` |
| 흐린 텍스트        | `#9CA3AF` |
| 스케일 바          | `#3D5AFE` |

**반대로 "토큰을 보여주는 영역"(`Swatch · *`)은 반드시 변수/스타일을 바인딩한다.**
변수 값을 고치면 문서가 따라 움직여야 한다. 여기에 hex 를 박으면 문서가 즉시 거짓말이 된다.

폰트는 `Pretendard` → 없으면 `Inter` 순으로 시도한다. 둘 다 실패하면 스크립트가 멈춘다.

---

## 6. 재실행 규칙

스크립트는 **멱등**이다. 실행하면 `Token Documentation — *` 프레임과
레거시 `Token Swatch` 프레임을 먼저 지우고 새로 그린다.
토큰을 고친 뒤 다시 돌리면 문서가 항상 현재 변수 상태와 일치한다.

---

## 7. 검증

```bash
node scripts/check-token-docs.mjs      # = npm run check:token-docs
```

`design/04-screens/figma-snapshot.json` 을 읽어 판정한다.
따라서 **문서를 그린 뒤 스냅샷을 다시 뽑고** 검사해야 한다.

판정 항목:

1. `01 Tokens` 페이지에 6개 문서 프레임이 전부 있다
2. 레거시 `Token Swatch` 프레임이 남아있지 않다
3. 문서 프레임 폭이 1280 이다
4. 카드 프레임이 214×136, `Swatch · *` 가 폭 190 이다
5. 각 문서의 카드 집합이 해당 컬렉션/스타일 목록과 **정확히 일치**한다 (누락 0 · 유령 0)
