# User Flows

**작성일:** 2026-09-13
**대상:** 허들링 앱
**기준:** PRD.md §3 사용자 시나리오 (유료 멤버 중심)
**총 시나리오:** 3개

화면 번호는 design/02-structure/screens.md 를 참조한다 (① 홈, ② 스킬 라이브러리, ③ 미션 상세, ④ 내 자산, ⑤ 허들링 픽).
각 시나리오는 2인칭 현재형으로 서술하며, 화면 간 이동은 `화면 N → 화면 M` 표기를 병행한다.

## 시나리오 1 · 이번 달 학습 시작

**목적:** PRD §3 시나리오 1 — 앱을 켜서 이번 달 미션을 확인하고 관련 스킬을 탐색해 실무에 적용한다.
**관련 화면:** 홈(①), 미션 상세(③), 스킬 라이브러리(②)

### 흐름

1. 당신은 앱을 엽니다. 홈 화면이 보이고 최상단에 이번 달 미션 카드가 진행률 수치와 D-day 배지와 함께 떠 있습니다. (① 진입)

2. 이번 달 미션 카드를 탭합니다. **화면 1 → 화면 3.** 미션 상세 화면으로 이동하며 제목, 설명, 마감일, 요구 산출물 스펙 박스, 제출 상태 배지가 보입니다. (③)

3. 미션 상세 화면을 아래로 스크롤하면 "관련 스킬 카드 추천" 섹션이 보입니다. 그중 하나를 탭합니다. **화면 3 → 화면 2.** 스킬 라이브러리로 이동하며 해당 카테고리 칩이 자동 선택된 상태로 카드 리스트가 필터링되어 있습니다. (②)

4. 카테고리 칩과 난이도 필터를 조정해 원하는 스킬 카드를 찾습니다. 리스트 위에는 "총 N건"이 표시되어 필터가 실제로 반영됐음을 확인할 수 있습니다.

5. 마음에 드는 스킬 카드를 탭합니다. (스킬 카드 상세는 PRD §6 시연 범위 밖 — 구조상 다음 이동 지점으로만 남깁니다.)

### 관련 컴포넌트

- Card, ProgressIndicator, Badge (①③)
- SpecBox, ExpandButton (③)
- SearchBar, Chip, SegmentedControl, Card, Badge (②)

### 예상 시간

약 1분 이내

## 시나리오 2 · 산출물 자산화

**목적:** PRD §3 시나리오 2 — 미션 수행 결과물을 제출하고, 피드백을 거쳐 승인된 산출물을 내 자산으로 전환한 뒤 판매 신청까지 이어간다.
**관련 화면:** 미션 상세(③), 내 자산(④)

### 흐름

1. 당신은 미션 상세 화면에서 산출물 작성을 마칩니다. 하단 고정 CTA 중 primary인 "제출하기"를 탭합니다. (③, 상태: default → submitting)

2. 파일 첨부와 설명 작성이 비어 있으면 제출하기 버튼은 화면에서 사라지지 않고 같은 자리에 disabled 상태로 남아 있습니다. 필수 항목을 채우면 버튼이 활성화됩니다.

3. 제출을 완료하면 제출 상태 배지가 "작성 중"에서 "제출 완료"로, 이후 "피드백 대기"로 전환됩니다. (③ 내에서 상태 전환, 화면 이동 없음)

4. 피드백을 확인하고 필요 시 수정 후 재제출합니다. 상태 배지가 "승인"으로 바뀌면, 승인된 산출물이 자동으로 내 자산 목록에 반영됩니다. **화면 3 → 화면 4.**

5. 내 자산 화면에서 방금 승인된 자산 카드를 확인합니다. 상태 배지는 기본값 "비공개"입니다. (④)

6. 자산 카드의 보조 액션 "판매 신청"을 탭합니다. 상태 배지가 "판매 신청 중"으로 전환되며 검수 진행 상황이 카드 안에 표시됩니다. (④ 내에서 상태 전환)

### 관련 컴포넌트

- BottomCTA, Badge, SpecBox (③)
- Card, ListRow, Badge, Chip (④)

### 예상 시간

제출 → 승인까지는 비동기(수 일 소요 가능), 화면 조작 자체는 1–2분 이내

## 시나리오 3 · 허들링 픽 탐색

**목적:** PRD §3 시나리오 3 — 다른 멤버가 만든 검증된 자산을 둘러보고 필요하면 구매로 이어간다.
**관련 화면:** 홈(①), 허들링 픽(⑤)

### 흐름

1. 당신은 홈 화면에서 하단 탭바의 "허들링 픽"을 탭합니다. **화면 1 → 화면 5.** 허들링 픽 화면으로 이동하며 검색바, 카테고리 필터 칩, 정렬 옵션, 픽 카드 그리드가 순서대로 보입니다. (⑤)

2. 카테고리 필터 칩 중 하나를 선택합니다. 리스트 위 "총 N건" 표시가 갱신되고 카드 그리드가 필터링됩니다.

3. 정렬 옵션을 "인기순"으로 바꿔 카드 순서를 재정렬합니다.

4. 마음에 드는 픽 카드의 찜 아이콘을 탭합니다. 버튼이 outlined에서 filled로 반전되어 찜 상태임을 확인합니다.

5. 카드 자체를 탭합니다. **화면 5 → (픽 상세, 시연 범위 밖 참고 화면).** 상세 화면에는 제작자 배지·별점·가격이 상단에 모여 있고, 하단에는 찜+보조 액션(outlined)+구매하기(filled) 3분할 BottomActionBar가 고정되어 있습니다.

6. "구매하기"를 탭하면 구매 플로우로 이어집니다. (결제 정산은 PRD §12 제외 사항 — 본 시연 범위 밖)

### 관련 컴포넌트

- TabBar (①)
- SearchBar, Chip, SegmentedControl, Card, PriceBlock, Badge (⑤)
- (참고, 픽 상세) SpecBox, BottomActionBar, ExpandButton

### 예상 시간

약 1분 이내 (구매 단계 제외)

## 가정 로그

PRD·analysis.md에 근거가 없어 구조상 판단으로 정한 것들. Phase 3·4에서 뒤집힐 수 있다.

- **시나리오 1-3** "관련 스킬 카드 탭 시 해당 카테고리 칩이 자동 선택된 상태로 진입" —
  PRD에 명시 없음. 화면 2의 필터 구조(패턴 3)를 재사용하기 위한 구조적 결정.
- **시나리오 2-4** "승인 시 산출물이 자동으로 내 자산에 반영" —
  PRD §3 시나리오 2의 "승인된 산출물을 내 자산으로 전환"을 자동 반영으로 해석.
  사용자가 직접 전환하는 흐름이라면 화면 4에 전환 액션이 추가로 필요하다.
- **시나리오 2-5** 신규 자산의 기본 상태를 "비공개"로 가정 (PRD §8 Asset.visibility 기본값 추정).
