## UX 패턴

### 1. 진행 상태를 화면 최상단에 수치로 선언한다

**근거:** 002-toss-pay-progress.png

곡선 프로그레스 인디케이터 아래 `35% 완료`를 화면에서 가장 큰 텍스트로 배치하고,
바로 아래 파란 풀폭 CTA 하나만 둔다. 사용자가 화면에 들어온 순간 "지금 어디까지 왔고,
다음에 뭘 눌러야 하는지"가 두 요소로 끝난다.

**허들링 적용:** 화면 1 홈 — 이번 달 미션 카드의 진행률을 카드 최상단에 수치로.

---

### 2. 카드 하나가 "정보 + 액션"으로 완결된다

**근거:** 001-toss-home.jpg

계좌 카드 안에 `금액(대형) + 기관명(소형 회색) + 우측 pill 버튼(송금/내역)` 행을 쌓고,
카드 맨 아래에 `계좌개설 · 카드발급 · 대출받기` 텍스트 링크 행을 붙인다.
카드 밖으로 나가지 않고 그 안에서 다음 행동까지 이어진다.

**허들링 적용:** 홈 미션 카드, 내 자산 카드 — 카드 하단에 상태별 액션 링크 행.

---

### 3. 검색바 → 필터 칩 → 카드 리스트 3단 고정 구조

**근거:** 007-dmand-mentor-list.png, 013-dmand-search-list.png

탐색형 화면은 예외 없이 `검색바 → 칩 필터 행(가로 스크롤) → 결과 리스트` 순서다.
칩은 선택 시 검정 filled, 미선택 시 흰 배경 + 회색 테두리로 상태가 한눈에 구분된다.

**허들링 적용:** 화면 2 스킬 라이브러리(카테고리 6종 + 난이도), 화면 5 허들링 픽.

---

### 4. 결과 개수를 리스트 위에 명시한다

**근거:** 011-dmand-search-home.png(총 8건), 012-dmand-search-filter.png(총 53건), 013(총 520건)

필터를 적용한 결과의 총 건수를 리스트 바로 위에 작은 볼드로 고정 노출한다.
필터가 실제로 작동했다는 피드백을 텍스트 한 줄로 해결한다.

**허들링 적용:** 스킬 라이브러리·허들링 픽·내 자산 필터 결과 상단.

---

### 5. 탭으로 검색 결과의 축을 나눈다

**근거:** 011 / 012 / 013 (공고 · 기업 · 커뮤니티)

같은 검색어에 대해 결과 종류를 상단 언더라인 탭 3개로 분리한다.
선택 탭만 검정 볼드 + 하단 2px 언더라인, 나머지는 회색 레귤러.

**허들링 적용:** 통합 검색 시 `스킬 · 자료 · 픽` 축 분리 (시연 범위 밖이나 구조로 남김).

---

### 6. 하단 고정 CTA는 primary 1개 + 회피 경로 1개

**근거:** 004-toss-pay-benefit.png

화면 하단에 파란 풀폭 `동의하기` 버튼을 두고, 그 아래 테두리 없는 텍스트 버튼 `나중에`를 둔다.
primary는 언제나 한 개이고, 두 번째 선택지는 ghost로 무게를 낮춘다.

**허들링 적용:** 화면 3 미션 상세 — `제출하기`(primary) + `임시저장`(ghost).

---

### 7. 조건 미충족 시 CTA는 사라지지 않고 disabled로 남는다

**근거:** 017-bbaegi-payment-input.png

입력이 비어 있는 동안 `카드 등록` 버튼은 회색 배경 + 회색 텍스트로 같은 자리에 존재한다.
버튼을 감추지 않아 "여기가 끝 지점"이라는 정보가 유지된다.

**허들링 적용:** 자산 등록 폼, 미션 제출 폼의 하단 CTA.

---

### 8. 빈 상태는 문장 한 줄로 끝낸다

**근거:** 009-dmand-search-empty.png

검색 진입 직후 화면은 `최근 검색어가 없습니다.` 회색 문장 한 줄만 중앙에 둔다.
일러스트도 버튼도 없다. 여백 자체가 "아직 아무것도 없음"을 말한다.

**허들링 적용:** 내 자산 비어있음, 검색 결과 없음 — 최소 엠티뷰.

## 시각 패턴

### 9. 컬러는 액션과 상태에만 쓴다

**근거:** 001, 004, 005-toss-pay-map.png, 012

토스는 화면 대부분을 흰 배경 + 회색 텍스트로 유지하고, 파랑은 CTA 버튼·강조 숫자·
체크 아이콘에만 쓴다. 005에서는 지도 위에 흰 카드를 얹고 카드 안에서만 파란 버튼을 쓴다.
디맨드도 동일하게 파랑을 `팔로우` 버튼과 D-day 배지에만 배분한다.

**허들링 적용:** color-primary는 화면당 CTA 1곳 + 상태 배지로 제한.

---

### 10. 연한 배경 위 흰 카드로 밀도를 확보한다

**근거:** 007-dmand-mentor-list.png

배경을 연보라로 깔고 카드를 순백으로 띄운다. 그림자를 거의 쓰지 않고도
카드 경계가 분리되어, 카드를 촘촘히 쌓아도 답답해 보이지 않는다.

**허들링 적용:** PRD §9 "정보 밀도 높지만 압도적이지 않음"의 직접 해법 —
color-bg(연한 surface) + color-surface(흰 카드) 2층 구조.

---

### 11. 여백을 채우지 않는다

**근거:** 014-bbaegi-payment-manage.png, 017

설정 화면에 항목이 하나뿐이어도 `결제 카드 관리` 한 행 + 구분선만 두고 나머지를 비운다.
등록 폼도 입력 필드 4개 아래를 전부 여백으로 두고 CTA만 하단에 고정한다.

**허들링 적용:** 자산이 적은 초기 사용자의 내 자산 화면 — 억지로 채우지 않는다.

---

## 컴포넌트 패턴

### 12. 상태 배지 2종 체계 — 시간 배지와 분류 배지

**근거:** 011-dmand-search-home.png, 019-bbaegi-dictionary-detail.png

디맨드는 마감까지 여유가 있으면 `D-8`을 연보라 배경 + 파란 텍스트로,
당일 마감이면 `오늘마감`을 빨강 filled로 바꿔 같은 자리에서 긴급도를 색으로 전환한다.
빼기는 한 행에 `재활용 불가능`(회색 = 속성)과 `일반`(연파랑 = 분류) 두 종류를 함께 쓴다.

**허들링 적용:**

- 미션 D-day → 여유(soft primary) / 임박(danger) 전환
- 스킬 카드 → 난이도(회색 속성) + 무료·유료(컬러 분류) 2종 병기
- 자산 검수 상태 → 비공개/신청중/판매중 분류 배지

---

### 13. 리스트 행 = 썸네일 + 제목 + 메타 + 우측 액션

**근거:** 012-dmand-search-filter.png, 019

`원형(또는 라운드 사각) 썸네일 + 제목(볼드) + 메타 한 줄(중점 · 구분)` 좌측 블록에
우측 끝 액션 버튼을 붙이는 행 구조가 반복된다. 019는 썸네일을 컬러 배경 라운드 사각으로 써서
이미지가 없어도 행이 비어 보이지 않게 한다.

**허들링 적용:** 스킬 카드 리스트, 허들링 픽 카드, 내 자산 행.

---

### 14. 토글 상태는 filled ↔ outlined로 뒤집는다

**근거:** 012-dmand-search-filter.png

`팔로우`는 파란 filled, `팔로잉`은 흰 배경 + 파란 테두리 + 파란 텍스트.
같은 크기·같은 자리에서 채움만 반전시켜 상태를 표현한다.

**허들링 적용:** 찜하기/찜함, 팔로우 계열 토글 버튼 variant.

---

### 15. 폼 입력은 라벨 내장형 filled 필드 + 2열 그리드

**근거:** 017-bbaegi-payment-input.png

입력 필드는 테두리 없는 회색 filled 박스이고, 라벨이 박스 안 상단에, 플레이스홀더가 아래에 들어간다.
짧은 값 두 개(`유효 기간` / `비밀번호 앞 두자리`)는 2열로 나란히 배치한다.
그 위에는 pill 세그먼트 2개(`개인카드` / `법인카드`, 선택 = 파란 filled)로 폼의 모드를 먼저 고른다.

**허들링 적용:** 자산 등록 폼(공개 범위 세그먼트 + 제목/카테고리/가격 필드).

---

### 16. 컬러 카드 그리드로 탐색을 유도한다

**근거:** 018-bbaegi-dictionary.png

리스트 대신 2열 컬러 카드(파랑·주황)를 쓰고, 각 카드에 질문형 카피와 일러스트를 넣는다.
"무엇을 볼지 모르는" 진입 지점에서 선택지를 감정적으로 제시한다.

**허들링 적용:** 홈 상단 카테고리 진입 블록, 허들링 픽 큐레이션 섹션.

---

### 17. 마켓 상세는 "구매 결정 요소"를 상단 한 화면에 모은다

**근거:** 020-kmong-pdp-overview.png

상단 이미지 아래에 `판매자 배지(Level 1) + 닉네임` → `제목 2줄` → `별점 5.0 (9)` →
`등급 탭(STANDARD / DELUXE / PREMIUM)` → `가격 66,000원(VAT 포함)` + 수수료 안내 순으로
한 화면 안에 결정에 필요한 정보가 전부 들어간다. 스크롤 없이 "누가·얼마에·평은 어떤지"가 끝난다.

**허들링 적용:** 허들링 픽 상세 — 제작자 배지, 제목, 검수 통과 표시, 가격을 첫 화면에.

---

### 18. 포함 내용은 회색 스펙 박스에 좌 라벨 / 우 값 2열로

**근거:** 021-kmong-pdp-tier.png

`제공 개수 1개 / 작업일 7일 / 수정 횟수 1회`를 테두리 없는 회색 filled 박스 안에
좌측 라벨(회색) · 우측 값(진한 회색) 2열로 정렬한다. 문단이 아니라 표로 읽히게 만든다.

**허들링 적용:** 허들링 픽 상세의 "포함 내용"(파일 수, 형식, 사용 조건),
스킬 카드 상세의 "사용 도구 / 난이도 / 예상 소요".

---

### 19. 마켓 화면의 하단 액션바는 3분할이다

**근거:** 020, 021, 023-kmong-pdp-seller.png

하단 고정 바를 `찜 아이콘 버튼(정사각 outlined) + 보조 액션(문의하기, outlined) +
주 액션(구매하기, 검정 filled)` 3분할로 고정한다. 주 액션이 가장 넓은 폭을 차지하고,
찜은 폭을 최소로 잡아 아이콘만 둔다.

**허들링 적용:** 허들링 픽 상세 — `찜 + 미리보기 + 구매하기`.
단, 패턴 6(토스)과 달리 여기서는 보조 액션이 ghost가 아니라 outlined다.
**마켓 화면은 3분할 outlined, 폼·동의 화면은 세로 2층 ghost**로 구분해 적용한다.

---

### 20. 긴 콘텐츠는 "더보기" 풀폭 버튼으로 접는다

**근거:** 023-kmong-pdp-seller.png

판매자 소개 이미지를 일정 높이에서 자르고, 바로 아래 테두리만 있는 풀폭 `더보기` 버튼을 둔다.
상세 탭은 `서비스 설명 · 전문가 정보 · 리뷰 (9)` 3분할이며 리뷰 탭에는 개수를 병기한다.

**허들링 적용:** 자산 상세의 미리보기 영역, 미션 상세의 이전 피드백 기록.

---

### 21. 선택한 항목을 카드로 쌓아 보여준 뒤 일괄 실행한다

**근거:** 027-kmong-ai-inquiry.png, 028-kmong-ai-compare.png

선택된 서비스 3개를 `썸네일 + 체크 표시 + 판매자 아바타 + 제목 2줄 + 가격` 카드로
가로 3열에 늘어놓고, 하단에 `3개 서비스 문의하기`처럼 **개수를 문구에 넣은 단일 CTA**를 둔다.
비교 화면(028)은 그 위에 연보라 박스로 `공통점 / 주요 특징` 요약을 먼저 보여준다.

**허들링 적용:** 자산 여러 개를 묶어 판매 신청할 때, 스킬 카드 다중 선택 후 실행.

## 우리 앱 적용 계획

### 시각 방향

- **베이스:** 연한 surface 배경 + 흰 카드 2층 (디맨드 방식) — PRD "정보 밀도 높지만 압도적이지 않음"
- **컬러 사용:** primary는 화면당 CTA 1곳 + 상태 배지로 제한 (토스 방식)
- **톤:** PRD §9 "따뜻하고 실험적 / 실험실 + 자산 라이브러리" → 차가운 금융 블루보다
  채도 있는 따뜻한 계열이 후보. 브랜드 컬러는 Phase 3에서 사용자 결정.
- **여백:** 콘텐츠가 적을 때 채우지 않는다 (빼기 방식)

### 필요 컴포넌트 (Phase 2·3 입력)

- Card (미션형 / 스킬형 / 자산형)
- Badge (시간형: soft·danger 전환 / 분류형 / 속성형)
- Chip (필터 · 선택 filled)
- SearchBar
- SegmentedControl (2~3분할)
- Button (primary filled / secondary outlined / ghost / disabled)
- ListRow (썸네일 + 제목 + 메타 + 우측 액션)
- ProgressIndicator (수치 병기)

  결제·다운로드 표현은 근거 없이 추정하지 않고, 크몽 패턴을 기준으로 Phase 2에서 정의한다.
- 학습 플랫폼(Class101·인프런) 계열은 이번 수집에 포함하지 않음. 미션·제출·피드백 흐름은
  PRD §3·§5 기준으로 Phase 2에서 직접 정의한다.
- 크몽 리뷰 탭 내부 화면은 수집하지 않았다. 별점 표기(`5.0 (9)`)는 020에서 관찰된 범위만 반영.
